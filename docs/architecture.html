Factory Inventory Management System

A full-stack demo application: a Vue 3 single-page app talks to a Python FastAPI backend that serves in-memory mock data loaded from JSON files. There is no database.

System architecture

Three tiers, two processes, one HTTP boundary.

Frontend · port 3000

  • Vue 3 SPA (Composition API), built and served by Vite
  • Router: Dashboard, Inventory, Orders, Demand, Spending, Reports
  • Shared state via composables: useFilters, useI18n, useAuth
  • API client: src/api.js (axios)
  • Charts: custom SVG and CSS Grid
REST / JSON
CORS open

Backend · port 8001

  • FastAPI app served by Uvicorn (server/main.py)
  • Pydantic models validate every response
  • apply_filters() and filter_by_month() filter in memory
  • Computes aggregates: dashboard summary, spending, quarterly reports
import at
startup

Data · in memory

  • server/mock_data.py loads JSON once at import time
  • server/data/*.json: inventory, orders, demand_forecasts, backlog_items, spending, transactions, purchase_orders
  • generate_data.py can regenerate sample data
  • State is lost on restart

Data flow

From a filter change in the UI to a rendered chart.

  1. User sets filters. Four global filters (time period, warehouse, category, order status) live in the singleton state of useFilters.js, shared by all views.
  2. View requests data. A view calls api.getOrders(filters) or a sibling. The client drops values equal to all and builds the query string; the period is sent as month.
  3. FastAPI receives the request. The route in server/main.py (for example GET /api/orders?warehouse=Tokyo&status=Shipped) binds the query parameters.
  4. Filtering happens in memory. apply_filters() and filter_by_month() operate on the lists loaded by mock_data.py. Aggregate endpoints add computed fields, such as low-stock counts or has_purchase_order on backlog items.
  5. Pydantic validates the response. response_model checks and serializes the result to JSON. If a JSON file changes shape, the matching model must change too.
  6. Vue renders. Raw responses are stored in refs (allOrders, inventoryItems); derived values such as totals, chart segments and fill rates are computed properties that update reactively.

Observations

Mismatches between frontend and backend found while reading the code.

Frontend calls that the backend does not serve

  • api.js defines /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET by backlog item), but main.py has no such routes. The getTasks call fails when the app loads.
  • Dashboard.vue uses <PurchaseOrderModal>, but no such component exists in client/src/components/, so Vue warns that it cannot be resolved.
  • main.py defines PurchaseOrder and CreatePurchaseOrderRequest models and imports purchase_orders, which suggests the feature is only partly implemented.
  • CORS allows all origins (*) and the API base URL is hard-coded to http://localhost:8001/api. Both are acceptable for a local demo but not for deployment.
